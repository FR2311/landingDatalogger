2 Introduccion
2.1 Proposito:
Este proyecto nació de la necesidad del INTI (Instituto Nacional de Tecnología Industrial) por querer visualizar los datos obtenidos por sus robots al realizar pruebas de laboratorio de una manera sencilla y técnica, dichos datos  recolectados consisten en lo siguiente, el robot realiza una prueba de laboratorio, la que sea y dentro de la jaula donde se encuentra el robot se coloca un datalogger en un punto específico para que esté a través de sus sensores, mida datos como temperatura, humedad y presión, datos que luego enviará a un servidor dentro del laboratorio a través de una red mosquito con un protocolo de mensajería mqtt que envia un archivo .xlsx, este servidor transmitirá los datos a una web alojada en el mismo servidor la cual lee el archivo en formato .xlsx que envía el datalogger para así poner los datos del archivo en dashboard que el usuario final puede leer de manera más sencilla y comprensiva.
2.2 Alcance:
El alcance de este producto consiste en nuestros requerimientos funcionales y no funcionales, los cuales son:
Requerimientos funcionales:
Adquisición de datos: El sistema debe medir temperatura, humedad y presión en tiempo real a través de sensores.
Transmisión de datos: El sistema debe enviar los datos de forma inalámbrica utilizando el protocolo MQTT. 
Almacenamiento local: El sistema debe guardar los datos en una tarjeta SD en formato .xls para análisis posterior.
Visualización de datos: El sistema debe mostrar los datos en una interfaz web en tiempo real con gráficas y valores numéricos.
Configuración del sistema: El sistema debe permitir configurar parámetros como frecuencia de muestreo, umbrales de alarmas y credenciales MQTT.
Alertas y notificaciones: El sistema debe generar alertas visuales en la interfaz web cuando los valores estén fuera de rango.
Exportación de datos: El sistema debe permitir descargar los datos almacenados en la tarjeta SD desde la interfaz web.
Autonomía del sistema: El sistema debe poder operar de forma autónoma alimentado por batería.
Requerimientos no funcionales:
Confiabilidad: El sistema debe funcionar de manera continua y estable, sin pérdida de datos.
Rendimiento: El sistema debe transmitir y mostrar los datos en tiempo real con una latencia menor a 2 segundos.
Eficiencia energética: El sistema debe maximizar la duración de la batería optimizando el consumo de energía.
Seguridad: El sistema debe autenticar el acceso a la interfaz web mediante usuario y contraseña.
Integridad de datos: El sistema debe garantizar que los datos almacenados y transmitidos no se corrompan ni se pierdan.
Mantenibilidad: El sistema debe ser fácil de actualizar y mantener tanto en hardware como en software.
Usabilidad: La interfaz web debe ser intuitiva, clara y adaptable a diferentes dispositivos.
Resistencia ambiental: El hardware debe resistir condiciones de laboratorio, variaciones de temperatura y humedad.

2.6 Resumen ejecutivo:
Nuestro objetivo en este proyecto es realizar un datalogger autónomo (Funciona con una batería) el cual se comunique con el servidor del laboratorio para que de esa forma pueda hostearse en el mismo una página web en la cual cualquier integrante del equipo del laboratorio puede revisar el estado de lo que se esté midiendo en ese momento por el datalogger.

4.4 Interfaces de software:
Pantalla de inicio de sesión:  a través de un usuario y contraseña el administrador podrá ingresar a los datos proporcionados en la página web
Menú principal:  en el menú inicial se encuentran las distintas secciones de datos disponibles 
Botones: ejecutan acciones determinadas
Formularios: a partir de ellos se permiten ingresar información
Mensajes de alerta: aparecen en el momento de informar errores o confirman acciones.
Pantallas de configuración: en esta sección se permiten modificar las preferencias del usuario.

4.5 Interfaces de comunicación:
Comunicación entre sensores y datalogger: los sensores transmitirán las mediciones de temperatura, humedad y presión al datalogger mediante las interfaces de comunicación correspondientes.
Comunicación inalámbrica: el datalogger enviará los datos al servidor de manera inalámbrica, evitando la necesidad de una conexión física.
Protocolo MQTT: se utilizará MQTT como protocolo de mensajería para transmitir los datos desde el datalogger hacia el servidor. Este protocolo permite una comunicación eficiente y de bajo consumo.
Comunicación entre servidor e interfaz web: el servidor procesa los datos recibidos y los pondrá a disposición de la aplicación web para que puedan ser visualizados en el dashboard.
Comunicación con la tarjeta SD: el datalogger almacenará localmente las mediciones en una tarjeta SD en formato xls  permitiendo conservar los datos incluso si se pierde temporalmente la conexión con el servidor.
